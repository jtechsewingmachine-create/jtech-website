# F-09 — Deploy (runbook)

Status: config in the repo; waiting on accounts (human). Hosting per D-031, plans per D-038.

## In the repo
- `render.yaml`: Blueprint for the Go API (`api/`, Singapore, `/healthz` health check, env vars; `PROXY_SECRET` generated by Render, `SUPABASE_SECRET_KEY` prompted).
- `web/vercel.json`: runs the enquiry proxy function in `sin1` (Singapore), next to the API.
- `web/lib/site.config.ts`: `SITE_URL` falls back to Vercel's production hostname, never localhost.

## Steps for the human (order matters)
1. **Render** (https://dashboard.render.com): sign in with GitHub → New → Blueprint → pick `jtech-website`. When asked, paste the Supabase **secret** key (`sb_secret_…`, Supabase → Project Settings → API Keys) into `SUPABASE_SECRET_KEY`. Do not paste it in chat.
2. When it is live, note the URL (e.g. `https://jtech-api.onrender.com`). Open `<url>/healthz` → `{"status":"ok"}`.
3. Render → jtech-api → Environment → copy the generated `PROXY_SECRET`.
4. **Vercel** (https://vercel.com): sign in with GitHub → Add New → Project → import `jtech-website` → **Root Directory: `web`**. Environment variables (Production and Preview):
   - `API_ORIGIN` = the Render URL from step 2
   - `PROXY_SECRET` = the value from step 3
   - `SITE_ENV` = `preview` (keeps Google out until launch; delete it to launch)
   - `SITE_URL` = only once a domain is attached, e.g. `https://www.example.in`
5. Deploy. Tell the builder the Vercel URL; the builder runs the live checks below.

## Live checks (builder, after step 5)
- Every route 200; unknown route 404; robots.txt `Disallow: /` and `X-Robots-Tag: noindex` while `SITE_ENV=preview`.
- Real enquiry submitted end to end → row appears in `public.enquiries` → test row deleted.
- Direct POST to the Render URL without the secret → 403.

## Launch (later, owner's call)
Attach the domain in Vercel, set `SITE_URL`, remove `SITE_ENV`, redeploy, submit the sitemap in Search Console.
